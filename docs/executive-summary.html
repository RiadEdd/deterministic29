Data release clearance

One dataset, one vendor, one cited decision.

Conclusion

The best prompt on Claude Sonnet 4.6 made no false allow in 66 decisions where the correct label is not allow. That sample is too small to call safe, and both configurations that can run on site made false allows on the adversarial set. I recommend against piloting this design. The model should read the request, and code should apply the rules and produce the label. That split is not built yet.

The problem

An engineer at a national energy company who sends a dataset to a vendor must check the data catalog, the approved-vendor list and the release rules, and sometimes ask compliance. Two things go wrong. Restricted data leaves because “summary” sounds harmless, or compliance becomes a queue that people work around. A wrong approval is an incident, reportable when the data is export-controlled subsurface data.

What I built

An LLM in a tool loop. It reads a plain-language request, calls four read-only lookups, and returns one label (allow, deny, needs-owner or abstain) with the id of the record row that decided it. I tested Claude Sonnet 4.6 and gpt-oss-20b, an open-weight model an air-gapped site could host.

The technical documentation also counts an unusable reply as wrong, which gives variant A 85% and 88%. Six of the baseline’s ten unusable replies hold two decisions, the first an allow. They are scored as no decision.

The rulebook text accounts for the accuracy gain. The numbered steps add an answer that can always be used: variant A returns a null record id when an abstain has no single row to cite, and the schema rejects it. A decision takes about five seconds.

Next steps

  1. Move the decision out of the model. The model names the dataset and every destination in the request. Code reads the ids, applies the rulebook, and returns the label and the citation. It goes to the pilot only if gpt-oss-20b, run locally, gives zero false allows on 40 adversarial cases.

  2. Hand the rulebook and the answer key to compliance. Governance freezes the rulebook under a version number and agrees in writing how many real decisions with no false allow the agent needs before it may approve alone. Compliance labels a new case set without seeing the agent’s answers.

  3. Run in shadow mode with the engineering team that sends the most datasets. Four weeks beside the current process. Compliance labels every request before seeing the agent’s answer, and each request the agent gets wrong becomes a test case. Stop on any false allow or on more than 10% disagreement. Otherwise decide on assist mode, where compliance still confirms every allow.

Caveat The rulebook, the 28 cases and every label are mine, and I amended the rules while labeling 14 of the 20 core cases. Zero false allows does not show the agent is safe: with 16 non-allow core cases, the true rate could still be about 17% at 95% confidence.
